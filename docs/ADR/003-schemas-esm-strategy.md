# ADR-003: Schemas Package ESM JSON Import Strategy

## Status
Accepted — 2026-08-03

## Context
The `schemas/` package at `@autonomous-lifecycle-protocol-alp/schemas` is a
collection of ~49 JSON Schema files. It declares `"type": "module"` and
relies on Node.js ESM JSON imports with the `with { type: 'json' }` assertion.

Current state:
- `schemas/index.js` exists and imports all 49 schema files using
  `import schema_x from './x.schema.json' with { type: 'json' }`.
- `schemas/package.json` declares `"main": "index.js"` (relative to package
  root).
- The file contains an `// AUTO-GENERATED. DO NOT EDIT.` header, suggesting
  it was previously generated by a build script.

The `scripts/gen-schemas-esm.cjs` script referenced in older project state
was removed during cleanup. The `index.js` is now hand-maintained or remains
as a static artifact.

## Decision
Retain the existing `schemas/index.js` as the package entry point. Do NOT
re-introduce a build script for regenerating it. If new schemas are added,
`index.js` must be updated manually (or the `// AUTO-GENERATED` comment
should be removed to reflect hand-maintenance).

## Rationale
- The ESM JSON import approach (`with { type: 'json' }`) is natively
  supported in Node.js 20+ (the project's `@types/node` is `^20.0.0`).
- No build step is needed for a pure-data package, keeping the schemas
  package trivial to publish.
- The `index.js` barrel file provides a clean `import schemas from
  '@autonomous-lifecycle-protocol-alp/schemas'` API for consumers.

## Consequences
- New schema files added to `schemas/` require a corresponding import in
  `schemas/index.js`.
- The `package.json` build script remains a no-op (`echo`).
- The `// AUTO-GENERATED. DO NOT EDIT.` header is misleading and should be
  removed or replaced with a descriptive comment in a future cleanup.
